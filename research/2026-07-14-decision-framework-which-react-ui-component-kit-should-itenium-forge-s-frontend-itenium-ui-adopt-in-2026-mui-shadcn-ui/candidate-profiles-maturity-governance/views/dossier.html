Which React UI component kit should itenium-ui adopt in 2026?
Finding — baseline layer only 14.07.2026

These four are not four options in one category — they are three categories. Material UI is a batteries-included library with a paid data grid: the row-grouping / aggregation / Excel-export tier an admin console actually wants costs $599/dev/yr [15]. Mantine is the same shape but 100% MIT — with a 94% single-maintainer bus factor [3] and an $18.5k/yr budget [25]. shadcn/ui is a code-distribution registry, not a dependency, and as of July 2026 it initialises new projects on Base UI, not Radix [21]. Base UI is the primitive layer under that — MUI-staffed, built by the ex-Radix / Floating-UI team, stable since Dec 2025 [20].

Picking "shadcn/ui" in 2026 therefore means picking MUI's primitives with none of MUI's licensing.

Exhibit C

The category collapse

Why four candidates are three things

The July 2026 realignment is the single biggest fact of the year for this file: npx shadcn init now selects Base UI, docs show Base UI examples first, and Radix stays supported but demoted [21]. The "vendor-neutral, no-lock-in" path and the "corporate MUI" path now share a runtime maintainer.

▣

Vendored library

Material UI · Mantine

A runtime dependency ships the components. You import them; you do not own them. Upgrades arrive through package.json. Styling comes with the box, and must be negotiated with.

⎘

Code registry

shadcn/ui

A CLI copies source files into your repo. Not a dependency — a delivery mechanism. You own every component after the first add, and future updates are opt-in, not automatic.

⊹

Primitives

Base UI

Behaviour, accessibility, focus management — no styles. The substrate the registry now sits on by default, and the layer both other categories increasingly route through.

"shadcn/ui vs Base UI" is not a real fork in the road — shadcn/ui is Base UI plus Tailwind styling plus a codegen CLI. The real fork is owned code (shadcn + Base UI) vs vendored library (MUI / Mantine).
Exhibit D

The cash gate

MUI X pricing · the only hard commercial gate in the field

Three of four are pure MIT with nothing gated. Material UI's core is MIT too. But the grid features an admin console actually needs sit behind MUI X — and an admin console walks straight into them.

Licence is perpetual + 12 months of maintenance; renewals may rise up to 7%/yr [15]. Seats = concurrent developers touching front-end code that uses Pro/Premium. 30-day non-production trial without a key [16].
TierPer dev / yrWhat it unlocks
Community (MIT) $0 Basic Data Grid, Date Pickers, Charts, Tree View, Scheduler
Pro $299 Multi-filtering, multi-sorting, column resizing, column pinning, date/time range pickers, advanced charts, tree-view drag-and-drop
Premium ← the gate $599 Row grouping · aggregation · Excel export — i.e. table stakes for an admin console
Enterprise $1,399 Premium + guaranteed response times, CSM · min. 15 seats
Enforcement — runtime, not build-time

A missing env var ships a watermark

Validation happens at render via LicenseInfo.setLicenseKey(). On failure the component renders a watermark and logs a console warning in production, not just in dev. There is no build-time check to catch it in CI [16].

Translation for itenium-ui

$599 × every front-end dev, forever

The moment the console needs grouped rows or an Excel-export button, MUI becomes a recurring line item. It is the single largest cost delta between the candidates — and the one none of the other three can charge you, because none of the other three ships an enterprise grid at all.

Trap 01 — the missing major

Material UI v8 does not exist

It went v7 → v9 to re-align its major with MUI X v9, which was already there [17]. Expect stale blog posts and LLM output to confidently reference a v8 that was never published.

Trap 02 — the frozen scope

The dead @base-ui-components package

Base UI renamed at 1.0: @base-ui-components/react → @base-ui/react [19]. The old scope is frozen at 1.0.0-rc.0 and still pulls ~400k downloads/week [31] — a live trap for anyone copying pre-2026 snippets.

Trap 03 — the roadmap promise

MUI's Tailwind story isn't shipped

Emotion is still a hard peer dep in v9 [7]. MUI's own roadmap files Emotion-independence and "better integration paths for teams using Tailwind CSS" as future work, and Pigment CSS is paused in alpha [18]. A commitment, not a feature.

What this baseline hands to the other angles

  1. Base UI is load-bearing for two of the four options — standalone candidate and shadcn/ui's default runtime. Its health (⭐ 10k, 311 open issues, MUI-funded, 7 months post-1.0) is a shared dependency, not an isolated one.
  2. MUI's Tailwind story is a roadmap item, not a shipped feature, and Emotion is still a hard peer dep in v9 — referred to the Tailwind-4 interop angle.
  3. Mantine is the maintenance winner and the bus-factor loser simultaneously. Both facts are real; the risk sits entirely on one person's continued interest.
  4. The only recurring cash cost in the field is MUI X Premium at $599/dev/yr, triggered by exactly the grid features an admin console needs — referred to the component-coverage angle.
