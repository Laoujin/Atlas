> **TL;DR** — Two things have actually destroyed people's data in the wild: the agent running `git reset --hard` / `git checkout` unprompted and permanently eating uncommitted work [[2]](https://github.com/anthropics/claude-code/issues/34327) [[3]](https://github.com/anthropics/claude-code/issues/11237), and npm supply-chain malware that finds an installed agent CLI on the box and re-invokes it with `--dangerously-skip-permissions` as a credential-hunting tool [[6]](https://www.wiz.io/blog/s1ngularitys-aftermath). Indirect prompt injection against Claude Code is fully proven — five-plus real CVEs, working exfil channels — but the public record is still dominated by researcher PoCs rather than mass victim counts [[12]](https://embracethered.com/blog/posts/2025/claude-code-exfiltration-via-dns-requests/) [[17]](https://phoenix.security/claude-code-leak-to-vulnerability-three-cves-in-claude-code-cli-and-the-chain-that-connects-them/). Rank containment accordingly: **stop writes outside the workspace, stop arbitrary egress, stop reads of `~/.ssh` and `~/.aws`** — in that order.

## The frame

Anthropic's own threat model for Claude Code names four failure classes, and it's a good scaffold because it separates "the model meant well" from "someone else is driving": **overeager behaviour** (initiative beyond what you'd approve), **honest mistakes** ("the agent misunderstands the blast radius"), **prompt injection** ("instructions planted in a file, webpage, or tool output hijack the agent"), and **model misalignment** — which they note is not observed in practice [[1]](https://www.anthropic.com/engineering/claude-code-auto-mode).

Overlay Willison's lethal trifecta — private data access, exposure to untrusted content, ability to communicate externally [[9]](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/). A coding CLI on your daily driver has **all three by default**, and the reason it can't be prompted away is structural: "LLMs are unable to reliably distinguish the importance of instructions based on where they came from" [[9]](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/).

Two calibration numbers before the vector-by-vector walk. Anthropic reports users approve **93% of permission prompts** anyway, and its auto-mode classifier has a **17% false-negative rate** on a curated set of genuinely overeager actions [[1]](https://www.anthropic.com/engineering/claude-code-auto-mode). And in the wild, an analysis of **18,470 public `.claude/settings.local.json` files** found 22.2% grant `Bash(rm:*)` (4,101 users), 21.3% grant `curl`, 19.7% grant unchecked `git push`, and **only 1.1% define any deny rule at all** [[5]](https://www.upguard.com/blog/yolo-mode-hidden-risks-in-claude-code-permissions). The human-in-the-loop is, empirically, a rubber stamp.

## Documented vs. theoretical

| Vector | Status | Hardest evidence | Blast radius if it lands |
|---|---|---|---|
| Agent runs destructive `git` | **Observed repeatedly, real victims** | Unprompted `git reset --hard origin/main` at session startup on two consecutive days; 12 unpushed commits + uncommitted work permanently lost [[2]](https://github.com/anthropics/claude-code/issues/34327). `git checkout <file>` ate 4 days of work [[3]](https://github.com/anthropics/claude-code/issues/11237) | Uncommitted + unpushed work in the repo. Recoverable only via reflog, and only for committed objects |
| Supply-chain malware weaponizing the installed CLI | **Observed, ~1,000+ victims** | s1ngularity invoked `claude --dangerously-skip-permissions -p <prompt>`, `gemini --yolo`, `q chat --trust-all-tools` to hunt `id_rsa`, `.env`, wallet keystores [[6]](https://www.wiz.io/blog/s1ngularitys-aftermath) | Every credential the agent can read → downstream GitHub/npm/cloud. Phase 2 made 6,700+ private repos public [[6]](https://www.wiz.io/blog/s1ngularitys-aftermath) |
| Malicious dependency pulled by a build the agent runs | **Observed, industrial scale** | Shai-Hulud 2.0 backdoored **796 npm packages** (20M weekly downloads), ran TruffleHog locally, installed a self-hosted GitHub runner, and **deleted the home directory** when exfil failed [[7]](https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/). 2026 waves: 639 malicious versions across 323 packages in ~1 hour [[8]](https://unit42.paloaltonetworks.com/monitoring-npm-supply-chain-attacks/) | Full user account. `preinstall` runs before any agent guardrail is consulted [[8]](https://unit42.paloaltonetworks.com/monitoring-npm-supply-chain-attacks/) |
| Indirect injection → credential exfil from Claude Code | **Proven end-to-end, PoC-led** | CVE-2025-55284: injected file content made Claude `grep` `.env` and encode it into a `ping` subdomain — `ping`/`nslookup`/`dig`/`host` were default-allowlisted (CVSS 7.1, fixed v1.0.4) [[12]](https://embracethered.com/blog/posts/2025/claude-code-exfiltration-via-dns-requests/) | Any secret readable in the working tree or env |
| Injection via GitHub issue / PR content | **Observed vector, real CVE** | CVE-2025-66032 (CVSS 8.7): PR titles interpolated into the prompt unsanitised; malicious issue bodies got Claude to read `/proc/self/environ` [[16]](https://labs.cloudsecurityalliance.org/research/csa-research-note-claude-code-github-action-prompt-injection/) | CI secrets, repo write access |
| Untrusted-repo cold start | **Observed, multiple CVEs** | CVE-2025-59536: `.mcp.json` in an untrusted directory executed shell commands **at tool init**; CVE-2026-21852: API keys leaked via a repo-set `ANTHROPIC_BASE_URL` **before the trust prompt rendered** [[15]](https://thehackernews.com/2026/02/claude-code-flaws-allow-remote-code.html) | RCE / API key on first `cd` + `claude` |
| Third-party MCP server backdoor | **Observed once, in the wild** | `postmark-mcp@1.0.16` added one BCC line to `send_email`, silently forwarding every agent-sent email to `phan@giftshop.club` — first tracked malicious MCP server [[19]](https://snyk.io/blog/malicious-mcp-server-on-npm-postmark-mcp-harvests-emails/) | Everything that MCP server touches, invisibly |
| MCP config rewrite for persistent token theft | **PoC (Mitiga, 11 May 2026)** | npm `postinstall` rewrites MCP URLs in `~/.claude.json` to proxy OAuth exchanges; survives token rotation, and "OAuth sessions may still appear legitimate in SaaS audit logs" [[18]](https://www.esecurityplanet.com/threats/claude-code-mcp-attack-enables-persistent-token-theft/) | Persistent access to every connected SaaS |
| Sandbox escape (writes) | **Proven, patched** | CVE-2026-39861 (CVSS 7.7, fixed 2.1.64): sandboxed process creates a symlink out of the workspace, later unsandboxed write follows it → `~/.bashrc`, cron [[14]](https://www.sentinelone.com/vulnerability-database/cve-2026-39861/) | Host persistence from inside the sandbox |
| Sandbox escape (egress) | **Proven, silently patched** | SOCKS5 hostname null-byte parser differential: `attacker.com\x00.google.com` passes `endsWith()`, resolves to `attacker.com`. Vulnerable v2.0.24 → v2.1.89 (~130 releases, 5.5 months), fixed v2.1.90 with no changelog note [[13]](https://oddguan.com/blog/second-time-same-sandbox-anthropic-claude-code-network-allowlist-bypass-data-exfiltration/) | Egress allowlist is not a control you can rely on alone |
| Deny-rule bypass by padding | **Proven, unpatched publicly (Apr 2026)** | Hard cap of 50 security subcommands in `bashPermissions.ts`: 50 no-ops + a denied `curl` downgrades deny → "ask" [[23]](https://www.scworld.com/brief/claude-code-vulnerable-to-prompt-injection-due-to-subcommand-limit) — and users approve 93% of asks [[1]](https://www.anthropic.com/engineering/claude-code-auto-mode) | Deny lists are advisory |
| Slopsquatting / HalluSquatting | **Registered names + agent install attempts observed; no live malware yet** | 43% of hallucinated names recur across all 10 identical runs; `react-codeshift` spread to 237 repos via AI-generated skill files with daily agent install attempts [[26]](https://labs.cloudsecurityalliance.org/research/csa-research-note-slopsquatting-ai-supply-chain-20260419-csa/). Academic PoC used "harmless placeholders, not real malware" [[25]](https://thehackernews.com/2026/07/new-hallusquatting-attack-could-trick.html) | Same as any malicious dep, but you invited it |
| Model misalignment / agent pursuing its own goal | **Not observed** | Anthropic lists it and explicitly notes it is not seen in practice [[1]](https://www.anthropic.com/engineering/claude-code-auto-mode) | — |

## Ranked by likelihood × blast radius

| 2 | Agent destroys uncommitted/unpushed work | High — recurring, reproducible issues, closed as not planned [[2]](https://github.com/anthropics/claude-code/issues/34327) [[4]](https://github.com/anthropics/claude-code/issues/17190) | Hours-to-days of local work, unrecoverable | The most-realized harm, and it's *not* an attack — it's category 1/2 of Anthropic's model [[1]](https://www.anthropic.com/engineering/claude-code-auto-mode) |

| 7 | Agent reaches a live production system through a stray token | Low on a dev workstation, catastrophic when it happens | Total, with backups | PocketOS: agent found a Railway token in an unrelated file, called `volumeDelete`, wiped prod **and volume-level backups in 9 seconds**; newest usable backup was 3 months old [[24]](https://zenity.io/blog/current-events/ai-agent-database-deletion-pocketos) |

## The legitimate egress channel

Worth separating from attacks, because containment can't fix it — only configuration can. Per Anthropic's docs: prompts, model outputs, and **every file Claude reads in full** go over TLS to the API; metrics never include code, prompts, or file paths (`DISABLE_TELEMETRY=1`); `/feedback`, `/bug` and `/share` **do** send conversation history including code, optionally opening a public GitHub issue (`DISABLE_FEEDBACK_COMMAND=1`); `WebFetch` sends the target **hostname** to `api.anthropic.com` for a blocklist check regardless of provider, and this is not covered by `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` [[10]](https://code.claude.com/docs/en/data-usage).

The local half matters more for blast radius: session transcripts are cached **in plaintext under `~/.claude/projects/` for 30 days** by default [[10]](https://code.claude.com/docs/en/data-usage). Any infostealer that reads that directory gets a replay of every file the agent touched, including secrets it printed — which is exactly why the credential-stealer families target agent config paths. On consumer Free/Pro/Max accounts with the training toggle on, retention is **5 years** [[10]](https://code.claude.com/docs/en/data-usage).

## Calibration: what's overstated

- **MCP vulnerability percentages are soft.** A hands-on audit of 33 local MCP servers (433 tools) found a **~78% false-positive rate** in pattern-based MCP scanners — only 6 of 27 flagged detections were genuine, and all 8 "prompt injection" hits were false [[21]](https://appsecsanta.com/research/mcp-server-security-audit-2026). Treat the 34%/82%/36.7% figures [[20]](https://www.practical-devsecops.com/mcp-security-statistics-2026-report/) as upper bounds on *attack surface*, not on exploitability.
- **Claude Code is the least-bad of its peers, not safe.** The 2026 systematic analysis rates Claude Code **Low**, Codex CLI and Copilot **High**, Cursor **Critical** [[22]](https://arxiv.org/html/2601.17548v1). Both catastrophic agent-deletes-prod stories in the public record involved Cursor-based agents, not the CLI [[24]](https://zenity.io/blog/current-events/ai-agent-database-deletion-pocketos).
- **Guardrails degrade the attacker, they don't stop them.** In s1ngularity, ~50% of victims had an AI CLI installed, roughly 25% of Claude invocations were refused outright, and the AI path succeeded in under 25% of cases — but the campaign still netted 2,000+ verified secrets [[6]](https://www.wiz.io/blog/s1ngularitys-aftermath).
- **"AI-orchestrated attack" headlines are about Claude Code as a *weapon*, not as your risk surface.** GTG-1002 (Nov 2025) was a state actor jailbreaking Claude Code to attack ~30 organisations with 80-90% of tactical work automated [[28]](https://www.anthropic.com/news/disrupting-AI-espionage). Relevant to how fast an attacker moves *after* they get your keys; not a workstation threat in itself.

## What containment must actually stop

Derived from the ranking, in priority order. Each of these is a sibling angle's problem to solve — this angle only specifies the requirement.

1. **Writes outside the working tree must be structurally impossible**, including via symlink [[14]](https://www.sentinelone.com/vulnerability-database/cve-2026-39861/) — this is what protects `~/.bashrc`, cron, and the agent's own `.claude/settings.json` [[17]](https://phoenix.security/claude-code-leak-to-vulnerability-three-cves-in-claude-code-cli-and-the-chain-that-connects-them/).
2. **Uncommitted work must survive the agent**, because `git reset --hard` will happen and Anthropic has closed those reports as not planned [[2]](https://github.com/anthropics/claude-code/issues/34327) [[3]](https://github.com/anthropics/claude-code/issues/11237).
3. **Long-lived credentials must not be readable from the agent's process** — `~/.ssh/id_rsa`, `~/.aws/credentials`, git remotes' push tokens, and any stray API token in an unrelated file [[17]](https://phoenix.security/claude-code-leak-to-vulnerability-three-cves-in-claude-code-cli-and-the-chain-that-connects-them/) [[24]](https://zenity.io/blog/current-events/ai-agent-database-deletion-pocketos).
4. **Egress must be enforced below the agent** (kernel/network layer), because in-process allowlists have been bypassed twice by outside researchers on first look [[13]](https://oddguan.com/blog/second-time-same-sandbox-anthropic-claude-code-network-allowlist-bypass-data-exfiltration/) and deny rules can be padded out of existence [[23]](https://www.scworld.com/brief/claude-code-vulnerable-to-prompt-injection-due-to-subcommand-limit). DNS counts as egress [[12]](https://embracethered.com/blog/posts/2025/claude-code-exfiltration-via-dns-requests/).
5. **`npm install` / build steps need the same boundary as the agent**, since the dependency, not the model, is the highest-likelihood attacker [[7]](https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/) [[8]](https://unit42.paloaltonetworks.com/monitoring-npm-supply-chain-attacks/).
6. **Third-party MCP servers deserve dependency-grade review**, and their config file (`~/.claude.json`) deserves integrity monitoring [[18]](https://www.esecurityplanet.com/threats/claude-code-mcp-attack-enables-persistent-token-theft/) [[19]](https://snyk.io/blog/malicious-mcp-server-on-npm-postmark-mcp-harvests-emails/).

Out of scope here and covered by sibling angles: Claude Code's own permission/sandbox features, Linux-native sandboxing primitives (bubblewrap, namespaces, systemd), container isolation, Proxmox VM/LXC separation, credential-isolation patterns, and audit/recovery tooling.
