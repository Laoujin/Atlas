Read before ordering

  • Most of the belt transfers. 7-Zip ships an official Linux build [17], CopyQ beats Ditto [15], QDirStat ★ 2.5k is WinDirStat's direct descendant [16], KDE Connect beats Phone Link [24], and PDFtk still runs as pdftk-java [19].
  • Three parts force a workflow change. ShareX becomes three or four separate tools; Sandboxie's "run this .exe throwaway and discard the changes" has no equivalent — Linux sandboxes confine by profile, not by shadowing an installed app [25]; and 1Password is fine only from the deb/rpm, never the Flatpak [20].
  • Two parts are not stocked anywhere. AutoHotkey — the 2026 consensus is still that you replace it with three to five separate projects and accept that window automation is desktop-specific [2] — and Power Automate Desktop, which is Windows MSI/Store-only with no Linux build at all [18].
  • "Just use X11" is no longer a plan. GNOME 50 removed the X11 session in March 2026 [12] and Plasma 6.8 drops it in October 2026 [13]. Every stamp on every card below assumes a Wayland session.

Aisle 03 · special order

AutoHotkey — the part made of four parts

AHK is four products in one: a hotkey daemon, a key remapper, a text expander, and a scripting language with window, GUI and COM automation. Linux splits these across three layers — and the layer determines whether the part survives Wayland at all.

Layer 1

Kernel input — evdev / uinput

Wayland-proof
keyd
★ 5.8k
layers
Layers, tap-hold, oneshot mods, macros, per-device and app-specific rules.Reads raw evdev and synthesises via uinput — works under X, Wayland and even a bare VT [3]. Linux-only; needs a root daemon.
kanata
★ 7.7k
layers+
Everything keyd does plus mouse output, chords, and one config you can reuse on Windows.Needs /dev/* access (avoid-sudo recipes exist); unicode output leans on ibus and is inconsistent, rapid key events can misfire [4].
keymapper
★ 1.1k
context
The closest thing to AHK's mental model — per-application context rules keyed on window title, class or process.Wayland context awareness requires the compositor to report focus: automatic on wlroots, otherwise via its GNOME Shell extension or a KWin script; process path may be unavailable [5].
kmonad
★ 5.0k
layers
QMK-style layers.Older, fewer features than kanata — which was inspired by it.
xremap
★ 2.1k
per-app
App-specific remapping, Wayland-aware.Needs a compositor-specific feature flag per desktop.
Layer 2

Text expansion

Wayland build experimental
Espanso
★ 14k
in stock
The real answer, and genuinely good — triggers, forms, shell and script extensions, a package registry.Ships separate X11 and Wayland builds; the Wayland one is still labelled experimental, requires setcap cap_dac_override+p, needs non-US layouts declared explicitly, app-specific config only works on KDE-Wayland if you also install kdotool ★ 378, and a newly plugged keyboard requires espanso restart [6].
Layer 3

Scripted GUI automation — where AHK dies

✗ No substitute
AutoKey
★ 3.9k
X11 only
The historical AHK-for-Linux: Python scripting, phrase expansion, window operations.It "is a Xorg application and will not function in a Wayland session" [7]. The only Wayland-capable variant is the autokey-wayland fork ★ 27 — GNOME-only, KDE "planned" [8]. A 27-star fork is not a foundation for your automation.

Manufacturer's notice — what Wayland makes structurally impossible

There is no equivalent of XGrabKey or XTestFakeInput. A client cannot read the keyboard while unfocused, cannot enumerate or move other clients' windows, and cannot inject synthetic input. Everything goes through a broker:

  • Input injection → the XDG RemoteDesktop / InputCapture portals backed by libei. Integrated since portal 1.17 with persistent authorisation since 1.21, which means "clients using XDG portals now work with any compositor that implements the portal, with no need for GNOME/KDE-specific APIs" [10] — but it is consent-gated, and text, gesture and tablet support are still being added.
  • Global hotkeys → the GlobalShortcuts portal, still patchy: wlroots' xdg-desktop-portal-wlr ships no implementation at all, so registration outright fails on Niri, Sway and River [11].
  • Window manipulation → nothing portable. "You won't find a single alternative, but you'll have to find multiple projects for specific features… Window automation is DE/WM specific" [2].

Aisle 04 · workshop bench

Three parts you rebuild, not replace

These three all have Linux answers. None of them has the same answer — the shape of the workflow changes, and knowing that up front is the difference between a smooth week and a bad one.

ShareX → assemble your own capture rig⚠ Field mod

Verdict: the single biggest workflow loss in the inventory.

Nothing on Linux bundles capture + annotate + OCR + custom uploader + history. You build it: Flameshot ★ 31k for the all-in-one, or grim+slurp feeding Satty ★ 2.3k if you want the Wayland-native pipeline; ksnip ★ 3.3k as the third option; Kooha ★ 3.5k or OBS ★ 74k for video; NormCap ★ 2.7k for the OCR slot.

Flameshot's own documentation enumerates the Wayland breakage — repeat portal prompts on GNOME, multi-monitor overlay bugs, shortcuts that do not fire — and states plainly: "We cannot do anything about it!" [14]. Custom uploaders become a shell script; that part is actually an upgrade.

Sandboxie → confinement by profile, not by shadow⚠ Field mod

Verdict: "run this throwaway and discard the changes" has no direct equivalent.

Sandboxie is Windows-only and kernel-driver based [32]. The mental model is what breaks: Sandboxie shadows the writes of an app you already installed and lets you throw them away afterwards. On Linux, Firejail ★ 7.6k applies a namespace and seccomp profile at launch time, bubblewrap ★ 8.2k is the low-level primitive and ships no ready-made profiles, and Flatpak ★ 5.0k only confines apps you installed through Flatpak [25].

1Password → right product, wrong package will hurt⚠ Field mod

Verdict: fine on Linux — and one packaging choice decides that.

The full desktop client is there, with system-authentication unlock via your Linux user password, fingerprint or other biometrics, or a security key [21]. Install the deb or rpm (or AUR, or the tar.gz). Do not install the Flatpak: it loses system authentication, loses the SSH agent, and loses unified app↔browser unlock [20] — three things you will notice on day one.
