> **Decision — pick KDE Plasma 6.7 on Wayland.** It is the only desktop that natively covers per-monitor panels, per-screen wallpaper, arbitrary fractional scaling, per-screen ICC profiles (now usable *together* with HDR) and — new in 6.7, after 21 years of requests — per-screen virtual desktops [[1]](https://kde.org/announcements/plasma/6/6.7.0/)[[2]](https://www.omgubuntu.co.uk/2026/06/kde-plasma-6-7-released). FancyZones comes back as [PlasmaZones](https://phosphor-works.github.io/plasmazones/) ⭐ 296 (Jul 2026) [[3]](https://github.com/fuddlesworth/PlasmaZones). **What it costs:** Stardock Fences has no equivalent — that workflow disappears [[8]](https://www.stardock.com/products/fences/); DisplayFusion's monitor-splitting and one-click window-position profiles degrade to scripts; and X-Rite Color Assistant is replaced by copying your factory `.icm` files across and calibrating with ArgyllCMS/DisplayCAL, with the caveat that Plasma Wayland does not load VCGT curves [[34]](https://hub.displaycal.net/forums/topic/how-do-i-bake-in-vcgt-in-icc-profile/). Choose Wayland, not X11: Plasma 6.7 is the last release with an X11 session [[4]](https://blog.davidedmundson.co.uk/blog/596/) and 6.8 (Oct 2026) drops it [[5]](https://9to5linux.com/kde-plasma-6-8-desktop-environment-to-drop-the-x11-session-and-go-wayland-only), with 95% of Plasma 6.6 users already on Wayland [[6]](https://www.phoronix.com/news/KDE-Plasma-Wayland-Ex-X11).

## The DE choice is the whole decision

Your four tools are not applications you swap one-for-one — they are shell extensions. On Linux the shell *is* the desktop environment, so the DE you pick decides which of them can be replaced at all.

**Read the table this way:** KDE gives you roughly 80% of DisplayFusion plus something Windows itself cannot do (per-screen virtual desktops). GNOME needs three extensions to get to a per-monitor taskbar and zone snapping, and still cannot put a different wallpaper on each screen. A tiling WM makes FancyZones irrelevant but deletes the Fences workflow and the taskbar concept entirely.

## Per-monitor taskbars and restore-on-dock: what actually exists

**Taskbars: solved, natively.** Plasma places a panel on any screen and 6.3 added panel cloning so the second and third monitor get an identical bar without re-configuring [[40]](https://alternativeto.net/news/2025/2/kde-plasma-6-3-improves-fractional-scaling-system-monitoring-panel-cloning-and-much-more/). The "show only tasks from current screen" filter exists, but there is a live NVIDIA-specific bug where the setting stops being honoured after resume from suspend, fixed by `systemctl restart --user plasma-plasmashell.service` [[14]](https://discuss.kde.org/t/solved-show-only-tasks-from-current-screen/12191). Given your GPU, expect to hit that.

**Restore-on-dock/undock: the honest answer is "partially, and only just".** Two things are converging:

1. **Compositor-side.** KWin has been sanitising window geometry on output removal for a decade; the canonical "windows do not survive an unplug" bug is closed as a duplicate of a fixed one [[28]](https://bugs.kde.org/show_bug.cgi?id=161325), but forum traffic shows the class of problem persisted.
2. **Protocol-side, and this is the real fix.** `xdg-session-management` was merged after six years and shipped in wayland-protocols 1.48 on 1 Apr 2026 [[26]](https://www.phoronix.com/news/Wayland-Protocols-1.48). KWin implements it as of Plasma 6.7 [[25]](https://blogs.kde.org/2026/04/18/this-week-in-plasma-per-screen-virtual-desktops-and-wayland-session-restore/). KDE is explicit that this is foundational: the remaining gate is "toolkits, libraries, and apps to implement support" [[25]](https://blogs.kde.org/2026/04/18/this-week-in-plasma-per-screen-virtual-desktops-and-wayland-session-restore/).

In practice for 2026: install RememberWindowPositions ⭐ 246, which restores position, size, screen and virtual desktop per application, tested on Wayland and X11 on Plasma 6+ [[27]](https://github.com/rxappdev/RememberWindowPositions). Its caveats matter — caption matching at an 85% threshold misfires on titles containing counters, and its Session Restore interaction is unofficial and has caused crash loops [[27]](https://github.com/rxappdev/RememberWindowPositions). For the *monitor* half of docking, kscreen already keys configuration to the connected-output set; if you end up outside KDE, kanshi ⭐ 718 is the standard hotplug profile switcher and can blank the laptop panel when docked [[29]](https://wiki.archlinux.org/title/Kanshi)[[50]](https://github.com/emersion/kanshi).

## Fences: no equivalent. Plan to lose it.

Fences 6 does four distinct things: shaded moveable icon groups, **automation rules** that sort new files into groups, roll-up mini-windows, and Peek (Win+Space to float the fences above all windows), plus Folder Portals that mirror an arbitrary folder onto the desktop [[8]](https://www.stardock.com/products/fences/).

- **KDE:** Folder View widgets are a genuine Folder Portals equivalent — you can place as many as you like on the desktop, each pointing at a different folder and filtered by regex or file type [[20]](https://docs.kde.org/trunk_kf6/en/plasma-desktop/plasma-desktop/folder-view.html). They are not fences: there are no automation rules, no roll-up, no Peek, and users report you cannot even hand-order icons inside a Folder View [[24]](https://bbs.archlinux.org/viewtopic.php?id=199261).
- **GNOME:** Desktop Icons NG has supported "stacking" — grouping files of the same type — since v34 [[21]](https://www.rastersoft.com/programas/ding.html)[[22]](https://extensions.gnome.org/extension/2087/desktop-icons-ng-ding/), and completed its GTK4 port in v51.0.0 in July 2026 [[23]](https://www.omgubuntu.co.uk/2026/07/ubuntu-desktop-icons-extension-gtk4-port). Grouping by type is not grouping by intent.
- **Tiling WMs:** there is no desktop layer, so the question does not arise.

The realistic migration is to stop using the desktop as a filing system: filtered Folder View widgets for the two or three folders you actually touch, and a launcher for everything else.

## Colour management and the X-Rite workflow

Your Legion's Color Assistant is a profile *loader*, not a calibrator — it restores Lenovo's factory sRGB / Rec.709 / HDR ICC profiles on panels sold as 100% sRGB or DCI-P3 [[10]](https://github.com/Tanmoy2504/X-Rite-Color-Assistant). So the migration is: copy the `.icm` files off the Windows install before you wipe it, drop them in `/usr/share/color/icc`, and assign them per display.

**Hardware calibration is fine.** ArgyllCMS is the engine and DisplayCAL the GUI; it supports essentially every colorimeter including the X-Rite/Calibrite i1 Display line, with vendor correction imports for i1 Display Pro and ColorMunki Display [[31]](https://displaycal.net/). Use the maintained Python 3 fork, displaycal-py3 ⭐ 1.6k, which targets Python 3.9+ [[32]](https://github.com/eoyilmaz/displaycal-py3). A 2026 walkthrough of the whole loop (calibrate → profile → `/usr/share/color/icc` → per-app colour management in digiKam/RawTherapee) is worth following, and it flags the trap: applying an ICC profile only inside a colour-managed app is insufficient because that app will not set the VCGT tables [[33]](https://arnebaeyens.com/blog/2026/linux-display-calibration/).

**The sharp edge is VCGT on Wayland.** KDE Plasma on Wayland does not expose an API to set the video-card gamma table, so calibration curves are not loaded into the GPU LUT; the correction has to live in the profile and be applied by the colour-management system instead [[34]](https://hub.displaycal.net/forums/topic/how-do-i-bake-in-vcgt-in-icc-profile/). For a factory-profile-loading workflow like yours that is acceptable; for hardware-calibrated grey tracking it is a real regression versus Windows.

**The protocol picture is finally good.** `color-management-v1` was merged upstream in Feb 2025 after five years and 800+ review comments, covering ICC profiles and HDR for both colour-aware and unaware clients [[37]](https://www.phoronix.com/news/Wayland-CM-HDR-Merged). KWin has assigned ICC profiles per screen since 2023 [[35]](https://www.phoronix.com/news/KDE-Wayland-Color-Mgmt), and Plasma 6.7 removed the last big compromise: "No longer do you have to choose between color management using an ICC profile or enjoying HDR content; now both are possible at the same time!" [[1]](https://kde.org/announcements/plasma/6/6.7.0/)[[36]](https://blogs.kde.org/2026/05/09/this-week-in-plasma-icc-profiles-%EF%B8%8F-hdr/). GNOME 50 (18 Mar 2026) shipped wp_color_management **v2** plus HDR screen sharing [[38]](https://release.gnome.org/50/).

## Fractional/mixed DPI and NVIDIA on a Legion

**Scaling.** Every major compositor now does per-monitor fractional scaling. KDE's advantage over GNOME is granularity: arbitrary percentages versus GNOME's 25% steps behind an experimental gsettings flag [[39]](https://botmonster.com/self-hosting/multi-monitor-linux-mixed-dpi-displays/)[[38]](https://release.gnome.org/50/). Plasma 6.3 reworked fractional scaling to align to the pixel grid, reducing blur and gaps [[40]](https://alternativeto.net/news/2025/2/kde-plasma-6-3-improves-fractional-scaling-system-monitoring-panel-cloning-and-much-more/). Mixed laptop-panel-plus-external is the standard case and works — the residual problem is XWayland, which renders at a single scale and gets rescaled for the other display, so expect soft text in older Electron apps, Qt5 tools and pre-2026.1 JetBrains IDEs, plus roughly 5–10% more GPU load than integer scaling [[39]](https://botmonster.com/self-hosting/multi-monitor-linux-mixed-dpi-displays/).

**NVIDIA, 2026.** The 595 branch (595.58.03, Mar 2026) enables `nvidia-drm.ko modeset=1` by default and adds DRI3 1.2 / DMA fences [[42]](https://ubuntuhandbook.org/index.php/2026/03/nvidia-595-58-03-released-with-better-wayland-linux-gaming-support/); it also raises the minimum Wayland version to 1.20 [[43]](https://9to5linux.com/nvidia-595-linux-graphics-driver-promises-wayland-1-20-support-beta-out-now). A May 2026 field report on 595.71.05 + Plasma 6.6 concludes explicit sync in Wayland and KWin has "remov[ed] a category of glitches that affected NVIDIA on Wayland specifically", and that multi-monitor with mixed refresh rates "works without thinking about it" — with VRR sometimes needing manual `kscreen-doctor` configuration [[41]](https://falcao.org/posts/nvidia-fedora-kde-wayland/). The open kernel modules are now the default, and mandatory on Blackwell [[41]](https://falcao.org/posts/nvidia-fedora-kde-wayland/).

**The Legion-specific risk is hybrid graphics with dGPU-wired outputs.** On many Legion models the internal panel is driven by both GPUs but every external output — HDMI and USB-C — is wired to the NVIDIA GPU only, and hybrid mode has produced blank external displays [[46]](https://forums.developer.nvidia.com/t/ryzen-7-gtx-1660ti-blank-screen-on-external-outputs-in-hybrid-graphics-mode/157800). A long-standing report has GNOME/mutter failing to initialise the dGPU and falling back to CPU rendering specifically when a *secondary* screen is attached to it, while single-display hybrid works fine [[44]](https://github.com/NVIDIA/open-gpu-kernel-modules/issues/161); NVIDIA's own forums carry the same complaint for KDE, GNOME and Cinnamon [[45]](https://forums.developer.nvidia.com/t/external-monitor-on-hybrid-nvidia-intel-laptop-on-wayland-is-unusable/304943), and Legion "Hybrid (iGPU only)" BIOS modes cause their own problems [[47]](https://bbs.archlinux.org/viewtopic.php?id=306247). ⚠ Before committing, boot a live Plasma 6.7 image with the external monitor plugged in and test all three BIOS graphics modes — this is the one item on this list that can be a hard blocker rather than an inconvenience.

## What you cannot get back

- Fences' automation rules, roll-up and Peek [[8]](https://www.stardock.com/products/fences/).
- DisplayFusion's monitor splitting, TitleBar buttons and Triggers [[7]](https://www.displayfusion.com/Features/).
- Hardware VCGT loading on Plasma Wayland [[34]](https://hub.displaycal.net/forums/topic/how-do-i-bake-in-vcgt-in-icc-profile/).
- Guaranteed window-position restore across dock/undock — the protocol exists, app adoption does not yet [[25]](https://blogs.kde.org/2026/04/18/this-week-in-plasma-per-screen-virtual-desktops-and-wayland-session-restore/)[[26]](https://www.phoronix.com/news/Wayland-Protocols-1.48).
