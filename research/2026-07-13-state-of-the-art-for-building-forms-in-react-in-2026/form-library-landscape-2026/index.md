> **Decision.** Default to [**React Hook Form**](https://react-hook-form.com) ⭐ 44.8k (Jul 2026) — 7.81.0 shipped 2026-07-05, 58.0M weekly downloads, 3 open issues, and a v8 beta with first-class React Compiler support [[1]](https://registry.npmjs.org/react-hook-form) [[2]](https://api.npmjs.org/downloads/point/last-week/react-hook-form) [[3]](https://github.com/react-hook-form/react-hook-form) ⭐ 44.8k [[5]](https://react-hook-form.com/migrate-v7-to-v8). Reach for [**TanStack Form**](https://tanstack.com/form) ⭐ 6.6k (1.33.2) when you need a genuinely framework-agnostic core, honest deep-path/array typing, or first-party Next/Start/Remix server-function adapters — and accept the verbosity its own docs admit to [[6]](https://registry.npmjs.org/@tanstack/react-form) [[69]](https://tanstack.com/form/latest/docs/framework/react/guides/form-composition). Reach for [**Conform**](https://conform.guide/) ⭐ 2.6k only when progressive enhancement / FormData-first is a requirement, not a preference [[52]](https://conform.guide/). [**Formik**](https://formik.org) ⭐ 34.3k is a zombie: zero commits in the six months to 2026-07-13, 704 open issues, and its author says on the record he stopped maintaining it in 2020 [[15]](https://github.com/jaredpalmer/formik) ⭐ 34.3k [[83]](https://x.com/jaredpalmer/status/1986851141645443151). [**React Final Form**](https://final-form.org) ⭐ 7.4k is in maintenance limbo — one bug-fix burst per year, no modern-React story [[21]](https://github.com/final-form/react-final-form) ⭐ 7.4k.

**RHF outweighs everything else combined by roughly 8×.** Its 3-open-issue backlog at 44.8k stars is the standout maintenance signal in the set [[3]](https://github.com/react-hook-form/react-hook-form) ⭐ 44.8k.

TanStack Form has been API-stable since v1.0 on 2025-03-02 [[68]](https://tanstack.com/blog/announcing-tanstack-form-v1); its cadence has slowed from ~8–9 releases/month in 2025 to ~3 in 2026 — post-v1 stabilisation, not decay, given 142 commits in H1 [[9]](https://github.com/TanStack/form/releases) ⭐ 6.6k. Its 91-issue/60-PR backlog against 6.6k stars is proportionally far worse than RHF's: a small-team-under-load signal, and the thing to price in if you adopt it.

## Dead, dying, alive

**Formik — zombie.** Last release 2.4.9 on 2025-11-10; the last *feature* release was 2.4.0 in May 2023 [[13]](https://registry.npmjs.org/formik). The 2.4.8/2.4.9 pair were React-19 JSX-namespace type patches **published by the github-actions bot, not a human** [[16]](https://github.com/jaredpalmer/formik/releases) ⭐ 34.3k. Zero commits between 2026-01-13 and 2026-07-13. The repo is not archived and there is no official notice; the community issue *"Is Formik no longer maintained?"* (opened Aug 2022) is still open with no maintainer reply [[17]](https://github.com/jaredpalmer/formik/issues/3613) ⭐ 34.3k, as is its successor, literally titled *"The best Form Library for react is abandoned?"* [[79]](https://github.com/jaredpalmer/formik/issues/3663) ⭐ 34.3k. Jared Palmer on X: *"I haven't maintained Formik since 2020"* — the React-19 release was a Copilot dogfooding exercise [[83]](https://x.com/jaredpalmer/status/1986851141645443151). Collaborator johnrom: *"I would move on to React Hook Form if you're starting fresh"* [[84]](https://github.com/jaredpalmer/formik/discussions/3526) ⭐ 34.3k. It still pulls 4.3M weekly downloads on pure legacy inertia [[14]](https://api.npmjs.org/downloads/point/last-week/formik).

**React Final Form — limbo, not death.** After a 3-year gap, the `final-form` core [[22]](https://github.com/final-form/final-form) ⭐ 3.0k shipped 5.0.0 (2025-06-07), converting Flow→TypeScript with no intended breaking changes, and 5.0.1 (2026-05-05) was *"a big batch of bug fixes that have accumulated"* [[23]](https://github.com/final-form/final-form/releases) ⭐ 3.0k [[18]](https://registry.npmjs.org/final-form). Bursty, not sustained: react-final-form had 0 commits in H2-2025 and 24 in H1-2026, with 360 open issues nobody works [[21]](https://github.com/final-form/react-final-form) ⭐ 7.4k. 7.0.1 was published by an account named `erikras-richard-agent`, not Erik Rasmussen personally [[19]](https://registry.npmjs.org/react-final-form). Architecturally frozen: no React 19, no Server Actions, no compiler story. Legacy-only.

**HouseForm — dead** (last release 2024-02-23) [[25]](https://api.npmjs.org/downloads/point/last-week/houseform).

**Because the size argument is dead.** `@hookform/resolvers` is 0.55 kB [[35]](https://bundlephobia.com/api/size?package=@hookform/resolvers@5.4.0), while `zod@4` is **61.79 kB untreeshaken** [[36]](https://bundlephobia.com/api/size?package=zod@latest) — a real Zod import shakes down well below that, but even conservatively the schema library is the same order of magnitude as, or larger than, the form library. The real win over Formik is the render model, not the bundle.

Conform is the smallest complete option and, being FormData-first, can run the same schema server-side and ship *no client validator at all* — an option the client-state libraries don't structurally have [[52]](https://conform.guide/) [[57]](https://judemiracle.com/articles/server-first-forms-with-conform-vs-react-hook-form.html). (TanStack's `createServerValidate` also validates server-side [[101]](https://github.com/TanStack/form/blob/main/docs/framework/react/guides/ssr.md) ⭐ 6.6k, but it still ships the client form model.)

## Controlled vs uncontrolled, and what it actually costs

The axis that actually separates these libraries. Note the distinction the marketing blurs: **"no re-render" always means no *form-level* re-render.** It does not always mean no *field-level* re-render.

| Library | State lives in | Keystroke re-renders… | Escape hatch (and its footgun) |
|--------------------|-----------------------------------|---------------------------|---------------------------------|
| React Hook Form    | DOM node + internal object, **outside React state**; `register` captures a ref | **Nothing.** The DOM node is written directly; no component renders [[45]](https://react-hook-form.com/faqs). ⚠ A `Controller`-wrapped field is controlled → that field renders | `useWatch`/`useFormState` isolate subscriptions to the calling component; `watch()` re-renders **the whole form** — the source of most perf complaints [[47]](https://react-hook-form.com/docs/usewatch) [[48]](https://github.com/orgs/react-hook-form/discussions/8117) ⭐ 44.8k |
| TanStack Form      | External TanStack Store, read via `useSyncExternalStore` | **The one `<form.Field>` subtree.** Fields are *controlled* render-props (`value={field.state.value} onChange={…field.handleChange}`) [[96]](https://tanstack.com/form/latest/docs/framework/react/guides/basic-concepts) — the form component itself does not render [[50]](https://tanstack.com/form/latest/docs/framework/react/guides/reactivity) | `form.Subscribe` re-renders only its subtree; `useStore`/`useSelector` **without a selector re-renders the host component on any state change** — same footgun as `watch()`, different name [[50]](https://tanstack.com/form/latest/docs/framework/react/guides/reactivity) |
| Conform            | **The DOM**; values read via `FormData` on demand [[52]](https://conform.guide/) | **Nothing.** Inputs stay native and uncontrolled; renders happen on validation events (blur/submit), not on input | ✗ None available: no `watch` equivalent, so cross-field derived UI mid-typing is awkward [[57]](https://judemiracle.com/articles/server-first-forms-with-conform-vs-react-hook-form.html) |
| Formik             | One controlled `values` object in React context | **The whole form.** `setState` per keystroke; issue #3400 measures **3 renders on a single keystroke** [[49]](https://github.com/jaredpalmer/formik/issues/3400) ⭐ 34.3k | ✗ None. Architectural, and it multiplies with field count |
| React Final Form   | `final-form` observer core | Depends on the `subscription` you declare | ⚠ The default is pessimistic: *"If no subscription is provided, it will default to subscribing to all form state changes"* [[53]](https://final-form.org/docs/react-final-form/types/FormProps) — an unconfigured RFF form gets Formik-grade renders |

So the honest ordering per keystroke is: **RHF (native input) = Conform: 0 renders < TanStack Form: 1 field subtree < Formik: the entire form.** RHF's zero collapses to TanStack's one the moment a field needs `Controller` — which, with MUI/AntD/Radix components that don't expose a native input's value/onChange contract, is *every* field. That is the single most under-reported fact in this comparison: **for a component-library-heavy app, RHF's uncontrolled advantage largely evaporates** [[48]](https://github.com/orgs/react-hook-form/discussions/8117) ⭐ 44.8k. (UI-kit wiring is a sibling angle in this expedition; treat it as a real selection input, not a footnote.)

**There is no credible cross-library benchmark in 2025–2026.** Every "comparison" post is qualitative [[54]](https://splitforms.com/blog/best-react-form-library-2026) [[55]](https://formisch.dev/blog/react-form-library-comparison/) [[58]](https://asoasis.tech/articles/2026-03-28-1453-react-form-libraries-comparison-2026/). RHF's own benchmark repo — the one its FAQ links — is `bluebill1049/react-hook-form-performance-compare`, ⭐ 33, measuring *mount time* under 6× throttle (RHF 3800 ms, Formik 5800 ms, Redux Form 16000 ms) against a Redux Form straw man, with no TanStack or Conform entrant [[46]](https://github.com/bluebill1049/react-hook-form-performance-compare) ⭐ 33. **Treat "RHF is fastest" as unverified against its actual 2026 rivals.**

⚠ **The perf conclusion that matters:** at scale all three modern libraries are fast by default and slow by misuse, and the variable is subscription placement, not library choice — the RHF maintainer's guidance on the canonical blowup (a large form with a root-level `watch` + `Controller`-wrapped AntD inputs) is *"subscribe as deep down the tree as possible"* [[48]](https://github.com/orgs/react-hook-form/discussions/8117) ⭐ 44.8k. Every one of these libraries has that same trap under a different name.

## TypeScript inference — where each one actually breaks

| Library | Type source of truth | Deep paths / arrays / unions | Where it leaks |
|--------------------|------------------------------------|--------------------------------|----------------|
| React Hook Form    | The **hand-written `useForm<T>` generic** — *not* the resolver schema; nothing enforces they agree | `Path<T>` is an eagerly-computed string-literal union with a recursion cut-off (`AnyIsEqual`), and non-tuple arrays index as `ArrayKey = number`, so `items.${number}.name` is accepted **with no index checking** [[60]](https://unpkg.com/react-hook-form@7.81.0/dist/types/path/eager.d.ts) [[61]](https://unpkg.com/react-hook-form@7.81.0/dist/types/path/common.d.ts) | `FieldValues = Record<string, any>` [[59]](https://react-hook-form.com/ts) → `useFormContext` returns `any` errors. Maintainer: *"a current limitation with V7, fixed in the next major"* — and v8 is **still not GA** [[62]](https://github.com/orgs/react-hook-form/discussions/8518) ⭐ 44.8k |
| TanStack Form      | **`defaultValues`** — the schema is validated against, but types don't come from it [[67]](https://tanstack.com/form/latest/docs/philosophy) | Best path machinery in the set: `DeepKeysAndValues` indexes array elements properly, handles tuples, distributes over unions, propagates parent nullability [[70]](https://unpkg.com/@tanstack/form-core@1.33.2/dist/esm/util-types.d.ts) | Optional/union fields need a `defaultValue` expressing their full range or inference is wrong; unions need manual casts in `onChange` [[82]](https://formisch.dev/blog/react-form-library-comparison/#tanstack) |
| Conform            | **The schema** (`useForm<Schema, FormValue, FormError>`) — genuinely single-source | No string-path union at all: `FieldName` is a **branded string** carrying phantom types, so names are *produced* (`fields.email.name`) via `getFieldset()`/`getFieldList()` [[75]](https://unpkg.com/@conform-to/dom@1.19.4/dist/form.d.ts) [[76]](https://unpkg.com/@conform-to/react@1.19.4/dist/context.d.ts). Discriminated unions handled explicitly by `Combine<T>` | Sidesteps TS-perf and depth limits entirely — the strongest inference story, at the cost of the FormData straitjacket |
| Formik             | Nothing | `FieldProps<V = any, FormValues = any>`, `name: string` [[77]](https://unpkg.com/formik@2.4.9/dist/Field.d.ts) | ✗ No path inference, no schema inference, no field-array typing. The TS guide only ever shows manually-supplied generics [[78]](https://formik.org/docs/guides/typescript) |
| React Final Form   | Nothing | `FieldProps` has `_FormValues` as a **phantom (unused) parameter**, `name: string`, and an `[key: string]: any` index signature that swallows typos [[80]](https://unpkg.com/react-final-form@7.0.1/dist/types.d.ts) | `withTypes<FormValues>()` types `Form`/`FormSpy` but **not `Field`** [[81]](https://unpkg.com/react-final-form@7.0.1/dist/index.d.ts). Worst TS story of the five |

**Two concrete RHF footguns an expert will hit.** (1) The stringly-typed contract breaks at runtime: a field typed `number` **silently becomes a `string`** when edited, and TS cannot catch it — maintainer-confirmed [[93]](https://github.com/orgs/react-hook-form/discussions/8617) ⭐ 44.8k. (2) Generic field wrappers broke under Zod v4: constraining `TSchema extends z.ZodType` makes `z.infer<TSchema>` resolve to `unknown` → *"Type 'unknown' does not satisfy constraint 'FieldValues'"*; the current workaround is to constrain to `z.core.$ZodType<any, any>` [[63]](https://github.com/orgs/react-hook-form/discussions/13205) ⭐ 44.8k. Transforming schemas also force `useForm<z.input<S>, unknown, z.output<S>>` [[64]](https://github.com/react-hook-form/react-hook-form/issues/11023) ⭐ 44.8k.

**And TanStack's "you never pass a generic" claim breaks the moment you factor out a reusable field component.** Its own docs concede *"a common criticism of TanStack Form is that it is verbose out-of-the-box"*, warn that the context escape hatch *"will not warn you when the types do not align. You risk runtime errors"*, and note that chaining `AppForm` extensions *"can lead to decreases in TypeScript performance"* [[69]](https://tanstack.com/form/latest/docs/framework/react/guides/form-composition). Community: *"I can't figure out how to properly type form or field… you have to pass 10 type arguments"*; maintainer Balastrong replies that a recommended wrapper pattern is still wanted [[71]](https://github.com/TanStack/form/discussions/922) ⭐ 6.6k. The sanctioned `createFormHook` + `withForm` answer still pushes you toward `AnyFormApi`/`AnyFieldApi`, *"where type safety is lost"* [[72]](https://matthuggins.com/blog/posts/building-a-reusable-form-component-library-with-tanstack-form).

**Ranking.** End-to-end schema→name→value inference: **Conform ≥ TanStack Form > RHF ≫ Formik ≈ React Final Form**. For *reusable generic field components* all of them degrade, but not equally: **TanStack is the least bad**, because `createFormHook`/`withForm` is at least a sanctioned, documented path [[69]](https://tanstack.com/form/latest/docs/framework/react/guides/form-composition) — RHF has no equivalent and its `useFormContext` type loss is a known v7 limitation deferred to a v8 that has not shipped [[62]](https://github.com/orgs/react-hook-form/discussions/8518) ⭐ 44.8k.

## Headless-ness and framework coupling

| Library | Headless? | Structure it imposes | Framework-agnostic core? |
|--------------------|-----------|----------------------|--------------------------|
| React Hook Form    | ✓ Fully   | Uncontrolled/ref model; non-native components must go through `Controller` | ✗ React-only |
| TanStack Form      | ✓ Fully   | Render-prop `<form.Field>` scaffolding per field — the verbosity tax [[69]](https://tanstack.com/form/latest/docs/framework/react/guides/form-composition) | ✓ **The only real one.** `@tanstack/form-core` + 7 adapters; react/vue/solid/svelte/angular all at 1.33.2, ⚠ preact lags at 1.30.2 and lit at 1.25.2 [[73]](https://registry.npmjs.org/@tanstack/svelte-form) |
| Conform            | ✓ Fully (least markup opinion) | ⚠ Everything must be expressible as `FormData`; non-native components (Radix/shadcn selects) bridge to a hidden native input via `useControl` [[52]](https://conform.guide/) | ⚠ `@conform-to/dom` exists but **only a React adapter ships** [[10]](https://registry.npmjs.org/@conform-to/react) — and it couples *upward* to Remix/Next server actions instead [[74]](https://conform.guide/integration/nextjs) |
| Formik             | ~ Partly  | Ships `<Field>`, `<Form>`, `<ErrorMessage>` components | ✗ React-only |
| React Final Form   | ✓ Fully   | Subscription-based render props | ✓ Real `final-form` core with multiple bindings — but stagnant [[18]](https://registry.npmjs.org/final-form) |

⚠ TanStack's own [comparison table](https://tanstack.com/form/latest/docs/comparison) marks RHF as "No" on React Compiler and SSR [[51]](https://tanstack.com/form/latest/docs/comparison). That is contradicted by RHF's shipped v8 beta, whose headline feature is React Compiler support with no config [[5]](https://react-hook-form.com/migrate-v7-to-v8). Read it as marketing.

## Validation layer and React 19 fit

[Standard Schema](https://standardschema.dev/) is the common interface Zod/Valibot/ArkType/Effect now implement [[109]](https://standardschema.dev/); which schema library you pick is a sibling question — what matters *here* is that only TanStack Form and Conform consume it with zero adapter code, while RHF needs `@hookform/resolvers` (0.55 kB, so this is ergonomics, not weight).

## Migration cost

| Path | Effort | Codemod | What breaks |
|---------------------------|-------------------------------|---------|-------------|
| **Formik → RHF**          | Moderate, mechanical, form-by-form | ✗ None exists [[86]](https://github.com/react-hook-form/codemod) ⭐ 26 | Mental-model flip: controlled `values` → uncontrolled refs. `<Formik>`/`useFormik()`→`useForm()`, `<Field>`→`register`, `useField()`→`useController()`, `useFormikContext()`→`useFormContext`/`useWatch`. Live values need `useWatch()`. The two libs can coexist app-wide but **not inside one form**, so shared field components must be forked [[85]](https://github.com/trussworks/formik-to-react-hook-form-migration-guide) ⭐ 22 |
| **Formik → TanStack Form**| Moderate — ⚠ *not* harder than Formik → RHF | ✗ | Both are `<Field>`-render-prop + controlled-value models, so the *shape* survives: `<Field name>`→`<form.Field name children={(field)=>…}>`, `values`→`field.state.value`, Yup schema→`validators` (Standard Schema, no adapter) [[96]](https://tanstack.com/form/latest/docs/framework/react/guides/basic-concepts) [[100]](https://github.com/TanStack/form/blob/main/docs/framework/react/guides/validation.md) ⭐ 6.6k |
| **RHF v7 → v8** (beta)    | Small, ~5 mechanical edits    | ✗       | `register` passes the real ref; `useFieldArray` `id`→`key`, `keyName` removed; `watch(callback)` → `subscribe()`; `setValue` no longer overwrites field arrays → `replace()` [[5]](https://react-hook-form.com/migrate-v7-to-v8) |
| **RHF → TanStack Form**   | ⚠ **Rewrite of the form layer** | ✗ No official guide — TanStack ships only a comparison page [[51]](https://tanstack.com/form/latest/docs/comparison) | `register()` string paths → `<form.Field name validators children={(field) => …}>` render props with manual `field.state.value` / `field.handleChange`. Every input component gets rewritten; validation moves from one resolver to per-field validators [[96]](https://tanstack.com/form/latest/docs/framework/react/guides/basic-concepts) |
| **React Final Form → RHF**| Moderate; closest exit from RFF | ✗       | RFF's `<Field>` render-prop → `register`/`useController`; `subscription` objects → `useWatch`/`useFormState`. You gain a TS story RFF never had [[80]](https://unpkg.com/react-final-form@7.0.1/dist/types.d.ts). ⚠ If you rely on the `final-form` core outside React, TanStack Form is the like-for-like target instead [[18]](https://registry.npmjs.org/final-form) |
| **anything → Conform**    | ⚠ Rewrite **+ server rework** | ✗       | You surrender client-owned form state. Needs a server action / Remix-style route action to submit to; in plain Vite+React *"the ergonomics suffer because there's no server action equivalent"* [[92]](https://splitforms.com/blog/best-nextjs-form-library-2026) |

The only real automated tool is `@hookform/codemod` — and it only does **v6→v7**, last released Aug 2021 [[86]](https://github.com/react-hook-form/codemod) ⭐ 26. Nothing else in this matrix has a codemod, so every migration is hand-work priced per form.

⚠ **Counter-intuitive, and the most actionable line in this table:** **Formik → TanStack Form is conceptually *closer* than RHF → TanStack Form**, because Formik and TanStack share the `<Field>`-render-prop + controlled-value model that RHF's `register` inverts [[96]](https://tanstack.com/form/latest/docs/framework/react/guides/basic-concepts) [[85]](https://github.com/trussworks/formik-to-react-hook-form-migration-guide) ⭐ 22. If you're escaping Formik and were going to touch every field anyway, TanStack is not a bigger lift than RHF — it's a *different* one, and the usual "Formik→RHF is the obvious path" advice quietly assumes otherwise.

## Pick this if…

**React Hook Form** — the default, and the burden of proof is on anything else. Pick it if you're building a SPA or a client-heavy app, you want the biggest ecosystem (58M weekly downloads means every edge case is already answered on Stack Overflow) [[2]](https://api.npmjs.org/downloads/point/last-week/react-hook-form), and you can live with stringly-typed paths. ⚠ Plan for v8: it's in public beta with breaking changes and no GA date [[4]](https://github.com/react-hook-form/react-hook-form/releases) ⭐ 44.8k [[5]](https://react-hook-form.com/migrate-v7-to-v8).

**TanStack Form** — pick it if any of: (a) you ship the same form logic to more than one framework — it's the *only* library that genuinely delivers this, with 7 adapters off one core (⚠ react/vue/solid/svelte/angular move together; preact and lit lag a few minors) [[73]](https://registry.npmjs.org/@tanstack/svelte-form); (b) you have deeply nested / array-heavy forms where RHF's `${number}` index-less paths hurt [[70]](https://unpkg.com/@tanstack/form-core@1.33.2/dist/esm/util-types.d.ts); (c) you're already in the TanStack ecosystem or on TanStack Start; (d) you want first-party Server-Function wiring rather than community glue [[101]](https://github.com/TanStack/form/blob/main/docs/framework/react/guides/ssr.md) ⭐ 6.6k. ⚠ Budget for building a `createFormHook` wrapper layer on day one — the raw API is verbose by the maintainers' own admission [[69]](https://tanstack.com/form/latest/docs/framework/react/guides/form-composition), and its 91-issue/60-PR backlog on a small team is the risk to price in [[8]](https://github.com/TanStack/form) ⭐ 6.6k.

**Conform** — pick it if progressive enhancement is a *requirement* (forms must work with JS disabled), or you're on Next App Router / React Router v7 and want one schema that provably cannot drift between client and server [[52]](https://conform.guide/) [[74]](https://conform.guide/integration/nextjs). ⚠ Don't pick it for a multi-step wizard with cross-field live previews — there is no `watch` and no client value store to hang derived UI off [[57]](https://judemiracle.com/articles/server-first-forms-with-conform-vs-react-hook-form.html). Bus-factor 1, 241k weekly downloads: a thin ecosystem when you hit an edge [[11]](https://api.npmjs.org/downloads/point/last-week/@conform-to/react).

**Formik** — never, for new work. Its author and its collaborator both say so [[83]](https://x.com/jaredpalmer/status/1986851141645443151) [[84]](https://github.com/jaredpalmer/formik/discussions/3526) ⭐ 34.3k. If you have it, the only question is migration budget; it is not a security or correctness emergency, so migrate opportunistically, form by form.

**React Final Form** — only if you already have it and it works. No React 19 story, no compiler story, worst TS story, 360 stale issues [[21]](https://github.com/final-form/react-final-form) ⭐ 7.4k.

**No library at all** — a real option for small forms (the Next-focused guides draw the line at roughly 1–5 fields) [[92]](https://splitforms.com/blog/best-nextjs-form-library-2026) [[54]](https://splitforms.com/blog/best-react-form-library-2026), and it just got more legitimate: **shadcn/ui went form-agnostic in Oct 2025**, with a `<Field>` family supporting RHF, TanStack Form, React 19 `useActionState` and custom [[90]](https://github.com/shadcn-ui/ui/discussions/9505) ⭐ 119k [[91]](https://ui.shadcn.com/docs/forms/react-hook-form). One of the biggest structural reasons RHF was *the* default — "shadcn's `<Form>` is an RHF wrapper" — no longer holds. The critique that form libraries *"re-create and manage the entire form's state in a separate JS object"* instead of using `FormData` and `ValidityState` has more teeth now than it did in 2023 [[94]](https://thomason-isaiah.medium.com/why-you-can-and-should-finally-ditch-your-form-library-e6b95bff01b6). A sibling angle in this expedition covers React's native form primitives in depth.

**RVF** — the option nobody names. It occupies Conform's progressive-enhancement niche with a more conventional API, ships current (8.1.3, 2026-07-04), and is the fallback if Conform's bus-factor-1 risk is disqualifying. ⚠ But at 972 stars and 31k weekly downloads it trades one bus-factor problem for a smaller one [[24]](https://github.com/airjp73/rvf) ⭐ 972.

1. ✗ *"State of React 2025 says RHF 74%, TanStack Form 21%."* The survey has no form-library question [[26]](https://2025.stateofreact.com/en-US/libraries/) [[28]](https://2025.stateofreact.com/en-US/other-tools/).

The 8.5-vs-15 kB figure is from RHF's own FAQ, citing 2022 versions [[45]](https://react-hook-form.com/faqs).
3. ✗ *"RHF has no React Compiler or SSR support"* (per TanStack's comparison table [[51]](https://tanstack.com/form/latest/docs/comparison)). RHF v8 beta's headline feature is zero-config React Compiler support [[5]](https://react-hook-form.com/migrate-v7-to-v8), and the repo pushed on 2026-07-12 [[3]](https://github.com/react-hook-form/react-hook-form) ⭐ 44.8k. Conversely, ✗ *"RHF is legacy"* is also false — 175 commits in the six months to 2026-07-13 [[3]](https://github.com/react-hook-form/react-hook-form) ⭐ 44.8k.
